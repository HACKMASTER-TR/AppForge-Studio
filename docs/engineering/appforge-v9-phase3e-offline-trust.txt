DESIGN
- Pure Ed25519 signatures, verified using local OpenSSL CLI.
- Strict 44-byte SubjectPublicKeyInfo DER Ed25519 encoding.
- Canonical JSON: duplicate keys/extra signed fields rejected.
- Signed domain separation: ROOT and RELEASE payloads use different prefixes.
- External pre-pinned root SPKI SHA256 and supplied root public DER are mandatory.
- Root metadata authorizes release signing keys and threshold 1..3.
- Root rotation metadata must bear BOTH the previously trusted root signature
  and a possession signature from the new root key.
- Root version and release sequence must meet externally supplied floors.
- Validity timestamps and 90-day maximum lifetime enforced.
- A release signature binds exact Phase 3D evidence SHA256 and root version.
- Even cryptographically valid test metadata must keep R2/public/Android OFF.

LIMITATIONS / REQUIRED BEFORE PRODUCTION
1. NO production private signing key is created or included. Tests generate
   temporary local keys, remove all private keys when finished, and do not
   write signed test releases to the AppForge evidence directory.
2. No embedded production root of trust: the verifier is a prototype. A real
   Android client needs immutable, independently provisioned trust anchor.
3. No persistent trusted high-water storage for rollback floors yet. Passing
   user-controlled --min-root-version or --min-release-sequence is not enough
   to guarantee anti-rollback across actual app restarts. Production requires
   secure persisted monotonic state and transition/update rules.
4. Rotation needs an independently reviewed old-root -> new-root handoff,
   certificate/root revocation strategy, and emergency recovery governance.
5. OPENSSL must be installed for cryptographic test verification. No fallback.
6. Does not upload, publish, modify repositories or touch the Android client.

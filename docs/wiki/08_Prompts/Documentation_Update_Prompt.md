# Documentation Update Prompt

Update wiki memory only when a change is durable.

Good candidates:
- architecture changes
- integration contracts
- release/deployment changes
- important decisions
- recurring bug root causes
- meaningful roadmap/status changes

Skip:
- tiny visual/copy/formatting changes
- one-off low-value bugs
- transient implementation detail

After updating, run the wiki audit and secret scan when practical.
